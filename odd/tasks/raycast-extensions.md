# Raycast extensions in Ferrocast (phase 0 prototype)
Branch: feat/raycast-extensions · Status: in progress (preparing to publish, L17)
Run extensions written for the Raycast Store inside Ferrocast: a Node.js sidecar with our own implementation of `@raycast/api`, whose React tree is rendered natively by the launcher.

## Specs
- S1 Notion "Mejoras Ferrocast / integracion apps raycast" (verbatim): "raycast tiene una gran comunidad debemos analizar si podemos hacer que las herramientas que hacen los usuarios que se pueden integrar en raycast podemos hacer que funcionen con nuestra herramienta, asi los usuarios que ya usen raycast y tengan descargadas herramientas de la store tambien las puedan usar en nuestra app https://www.raycast.com/store"
- S2 User decisions (L2, L4): analysis first, then "hagamoslo asi" — phase 0 prototype on a separate branch, not published.
- S3 Runtime (L4): use the user's Node if present and version >= 22; otherwise offer to download the official Node (verify its checksum) into Application Support. The app itself stays around 9-11 MB; no Node inside the bundle.
- S4 Phase 0 scope (Notion analysis): runtime + React reconciler + List, Detail, ActionPanel/Action, Clipboard, LocalStorage, toasts and preferences; try 20 popular Store extensions without OAuth or AI and measure how many work.
- S5 Security: third-party code runs with the user's permissions; only run extensions the user installed or chose, and say so in the UI. Do not download from Raycast's private Store API; use extensions already installed by Raycast (`~/.config/raycast/extensions`) or built from the MIT repository github.com/raycast/extensions.
- S7 User (L10, verbatim): "si midelo con 20 apps y haz todo lo necesario para que funcionen".
- S8 User (L17, verbatim): "prepara para que este todo listo y publicar".
- S6 Name: describe it as "runs Raycast extensions"; never present Raycast's brand as our own.

- L15 Live GUI re-test after 52d77da: typing still broke (keystrokes alternated between the host field and the extension's value, a restored draft made it visible; one run lost the first character and left the cursor at index 1). Root cause, found by reading the extension's own `@raycast/utils` (json-format `node_modules/@raycast/utils/index.js`): `useLocalStorage.setValue` calls `mutate(LocalStorage.setItem(..), { optimisticUpdate(c) { return c } })`, i.e. the "optimistic update" re-renders the field with the extension's CURRENT value (the one before this keystroke) the moment `onChange` runs, and the new value only arrives after `setItem` and a `getItem` revalidation (which also repeats the same stored value). `FormState::sync` (`view.rs`) treated every controlled value that was not in the sent history as an extension-side change, so each keystroke was followed by a render of the previous value that overwrote the host text (the cursor stayed), the next keystroke was typed on that stale base, and 52d77da also consumed history entries on the first echo so a repeated or out-of-order echo reverted the text too. Fix, all in `FormState` (`view.rs`): (a) a controlled value counts as the extension's doing only when it differs from the one it rendered last (`rendered`): re-rendering the unchanged value says nothing about what the user is typing (React would not re-render at all if the state had not changed, so extensions that filter input are not affected); (b) values we sent stay recognisable as late echoes for `ECHO_WINDOW` (5 s) and a match is never consumed (repeated and out-of-order echoes), after which the same value from the extension is its own change (`reset()` to a value sent earlier); `edit_at`/`sync_at` take the time for deterministic tests. Tests (RED observed: the unchanged re-render reverted `xa` to `x`, the model run failed at key 0 with `draft` instead of `dhraft`, the repeated echo `abc` reverted `abcde`): `a_re_render_with_the_unchanged_old_value_does_not_revert_typing`, `fast_typing_against_an_optimistic_extension_ends_with_host_equal_to_extension` (models the extension: optimistic old-value render per keystroke, read-back with lag 0 to 3, restored draft, cursor after the first character; host == extension at the end), `repeated_and_out_of_order_echoes_of_sent_values_never_revert_the_text`, `an_old_sent_value_is_an_extension_change_once_it_cannot_be_a_late_echo_any_more`; `form_state_keeps_edits_follows_controlled_values_and_drops_gone_fields` changed (a re-render with the same controlled value no longer resets the field).
