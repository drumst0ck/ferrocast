## Specs
- S1 (Notion bug, Alta, app) "Auto-update and Quit kill an active screen recording without saving its project file". Evidence: crates/app/src/app.rs:5904-5906, 3397-3408, 3014-3022; record_ctl.rs:735-740; swift/capture/main.swift:82. Problem: Automatic update install or Quit during a recording calls process::exit; the helper keeps screen.mov but project.json never gets the duration or camera/mic/system sources, so those tracks are orphaned and the editor shows a 0-length project. A running export is cancelled.. Repro: Update install = Automatic, start a recording with mic/camera, let the poller find a release (or Quit). Open the recording: no duration, no mic/camera.. Proposed fix: In quit() and start_update(), refuse or postpone while !record.is_idle() or an export runs; otherwise send Cmd::Stop and wait for Finished.. Confidence: confirmed by reading.
- S2 (Notion bug, Alta, app) "Holding Enter confirms a destructive Confirm dialog through key auto-repeat". Evidence: crates/app/src/draw.rs:972-973, 1419-1424 (no !k.repeat guard; Welcome has one at 1390); View::Update draw.rs:1382 same. Problem: Press-and-hold ↵ on Empty Trash, Shut Down, Restart, Log Out, Quit All Apps, Delete All clipboard entries, Move App to Trash or Update: the first press opens the Confirm view and auto-repeat confirms it.. Repro: Root search → Empty Trash → hold ↵ ~0.5 s.. Proposed fix: Ignore Enter when k.repeat; require a fresh press after the Confirm view is pushed (as View::Welcome does).. Confidence: confirmed.
- S3 (Notion bug, Alta, app) "Create Script silently overwrites an existing script; non-ASCII titles all map to '.sh'". Evidence: crates/app/src/draw.rs:1553-1571 (slug keeps ASCII alnum only; fs::write without exists() check). Problem: Same slug (e.g. 'Backup' vs backup.sh, case-insensitive APFS) replaces the user's script with the template; a title with only non-ASCII characters slugs to '' → hidden '.sh'.. Repro: Create script 'Test', edit test.sh, create another 'test' → edits gone. Title '日記' → scripts/.sh.. Proposed fix: Check exists() and add a suffix (reuse notes_ctl::unique_file_name); fall back to 'script' when the slug is empty.. Confidence: confirmed.
- S4 (Notion bug, Alta, core) "Sync: an item an older build cannot read is published as deleted and removed on every Mac". Evidence: crates/core/src/sync_io.rs:856-858 (from_items drops undeserializable values); crates/app/src/sync_ctl.rs:436-443 (tracker keeps the id as live); sync.rs:181-195 (id in tracker but missing from snapshot → tombstone at now). Problem: A Mac on an older build merges an item it cannot deserialize (new ClipKind/Theme variant); from_items drops it but the tracker lists it as live; next publish sends a fresh deletion that beats the original, so the newer Mac deletes its own item.. Repro: Scratch crate: B publishes {id:x, kind:"RichText"} at 5000; A merge_as → from_items 0 entries; publish at 9000 → Record{modified:9000, deleted:true}.. Proposed fix: Remove ids that from_items dropped from the tracker (or mark unparsed) so publish never tombstones them; keep opaque values.. Confidence: confirmed (experiment).
- S5 (Notion bug, Alta, extensions/CI) "A re-render of a lower extension screen closes the pushed screen and desyncs host and runtime stacks". Evidence: extensions-runtime/src/main.js:49-58 (flush sends render{depth} for any stack entry on commit); crates/app/src/ext_glue.rs:682-699 (ext_render truncates views and stack to depth). Problem: Screen 1 commits (useFetch revalidates) while screen 2 is pushed → host drops screen 2; runtime still has 2 entries → later action/field ids resolve against a Detail the user no longer sees; actions do nothing or run the wrong handler.. Repro: Fixture List pushes a Detail at 100 ms, setState at 300 ms → stdout render 1, render 2, render 1; ext_render truncates to depth 1.. Proposed fix: Only truncate on an explicit pop message from the runtime; otherwise update views[depth-1] in place.. Confidence: confirmed.
- S6 (Notion bug, Alta, extensions/CI) "Cache instances sharing a namespace overwrite each other's keys (data loss)". Evidence: extensions-runtime/src/api.js:165-193 (per-instance this._data snapshot; _save writes the whole snapshot; per-instance subscribers). Problem: @raycast/utils creates one Cache per hook; the second instance erases keys written by the first; subscribe() never fires for writes through another instance.. Repro: a=new Cache(); b=new Cache(); b.get('x'); a.set('one','1'); b.set('two','2') → file {"two":"2","z":"1"}, SUBS_FIRED 0.. Proposed fix: One module-level {data, subs} store per namespace shared by every instance.. Confidence: confirmed (experiment).
- S7 (Notion bug, Alta, macos) "AppleScript injection via file name in apps::trash() (Trash file from search)". Evidence: crates/macos/src/apps.rs:413-414 escapes only `"` (not `\`) before `delete POSIX file "{p}"`; reached from crates/app/src/app.rs:7650 (Act::Trash). Problem: A file name ending in `\"` becomes `\\"`: escaped backslash + real closing quote, so the rest of the name runs as AppleScript inside a Finder tell.. Repro: osascript with the string shape `x\" & (ASCII character 65) --` printed `x\A` (breakout confirmed). Not checked: whether do shell script runs inside the Finder tell.. Proposed fix: Use NSFileManager trashItemAtURL (as trash_app does) and drop osascript; at least escape `\` before `"`.. Confidence: confirmed breakout; suspected full code execution.
- S8 Repository rules: test-first (one RED test per rule, observed failing), tests through the public interface, docs/help updated when behaviour changes, CHANGELOG entry under [Unreleased] → Fixed per user-visible fix, strings for the 7 languages in crates/core/src/i18n/strings.tsv, `cargo test --workspace`, clippy and fmt clean (extensions-runtime: `npm test` and rebuild dist/runtime.js).
