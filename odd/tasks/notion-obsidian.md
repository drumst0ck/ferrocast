# Notion and Obsidian integrations
Branch: feat/integrations (worktree target/wt-integrations) · Status: planned, not started
Ferrocast talks to Notion (search, quick capture, send notes) and Obsidian (search with preview, new note, daily note, send/sync notes). Phases 1-2 are independent of the Notes app; Phase 3 waits until `feat/notes` is merged into master.

## How to execute this plan (read first)
- Work one task at a time, in order. Read this file down to `## Log` before each task; quote the S# you cover in the commit body.
- Test first: write the failing test for each rule, run it and see it fail, then implement. Assert every observable effect (returned values, toasts, saved files, Keychain writes, unchanged data on errors). Never call the real Notion API in tests; use the loopback server pattern (see Context C9).
- After each task: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`; for web docs also `cd web && npm run build`. Commit the task alone (Conventional Commit, about 400 changed lines max; split the task into two commits if needed). Record the commit hash in `## Tasks` and append a Log line with what was verified and what was not.
- Never `git commit -a` or `git add -A`: another session works in other worktrees of this repo. Add the paths you changed by name.
- Help text, settings index entries and docs (EN and ES) change in the same commit as the behavior they describe.
- Stop and ask the user, instead of guessing, when a spec is ambiguous or a task needs a decision not written here.

## Specs
- S1 User request (verbatim, L1): "al igual que tenemos un agente haciendo una app de notas, tu te encargaras de hacer integraciones de nuestra app tanto con notion como con obsidian elabora el plan que luego ejecutare con sonnet"
- S2 Notion scope (user answer, verbatim labels): "Buscar y abrir páginas desde el lanzador", "Captura rápida a una página o base de datos", "Enviar notas de Ferrocast a Notion". Not in scope: two-way sync.
- S3 Notion login (user answer, verbatim): "Token de integración interna (Recomendado)": the user creates an internal integration at notion.so/my-integrations, pastes its token, and shares pages with it. No server, token kept in the Keychain.
- S4 Obsidian scope (user answer, verbatim labels): "Buscar notas del vault y abrirlas", "Crear nota o añadir a la nota diaria", "Enviar/sincronizar notas de Ferrocast al vault", "Ver la nota en Ferrocast (Quick Look)".
- S5 Order (user answer, verbatim): "Integraciones primero, notas al final (Recomendado)": Phases 1-2 now; Phase 3 ("send notes") starts only after `feat/notes` is on master.
- S6 Secrets never appear in `settings.json`, logs, toasts, process arguments (`ps`), or crash output. Tokens are read from and written to the Keychain only.
- S7 Every network or file operation runs off the UI thread and reports failure with a toast that says what to do (for example "Notion rejected the token. Paste a new one in Settings → Integrations."). Nothing in the user's Notion or vault is deleted or overwritten silently.
- S8 Everything works with Obsidian closed except the actions that by nature open it (Open in Obsidian, Append to Daily Note, New Obsidian Note); those say so if Obsidian is not installed.

## Design notes (not specs)
- C1 HTTP: the app has no HTTP crate; every request is a `/usr/bin/curl` subprocess with the body and secrets passed through `-K -` on stdin (`crates/core/src/ai.rs:191` `curl_config`, `crates/app/src/services.rs:1688`). Keep that pattern; do not add reqwest/ureq. Results return through the `Bus`/`Msg` channel (`services.rs:165-176`, drained in `app.rs:~1760`); errors as `Msg::Toast` or typed results.
- C2 Notion API (checked 2026-10-22): header `Notion-Version: 2026-03-11`, `Authorization: Bearer <token>`. `POST /v1/search` body: `query`, `filter {property:"object", value:"page"|"data_source"}`, `sort {timestamp:"last_edited_time", direction}`, `page_size`, `start_cursor`; results have `url`, and page titles live in the `title`-type property. `POST /v1/pages` takes `parent` (`page_id` or `data_source_id`; internal integrations need one), `properties` (page parent: only `title`), and `markdown` (mutually exclusive with `children`). `PATCH /v1/pages/{id}/markdown` with `{"type":"insert_content","insert_content":{"content":"…","position":{"type":"end"}}}` or `replace_content`. Limits: 2,000 chars per text object, 100 blocks per request, respect `Retry-After` on 429. Page URLs moved to `https://app.notion.com/p/{id}` in June 2026: use `url` from the API, never build it. References: developers.notion.com/reference/post-search, /post-page, /update-page-markdown, /patch-block-children, /versioning.
- C3 Settings: struct `crates/core/src/models.rs:~206` with `#[serde(default)]`; tabs `SETTINGS_TABS` in `crates/app/src/draw.rs` (~6551) and the tests around `tests.rs:6780-6900` (`TAB_NAMES`); index `crates/core/src/settings_index.rs` ("every drawn row must be indexed"); raw `TextEdit` is banned in Settings code (a test scans the source); use the `group`/`row`/`field` helpers. Secret fields: see the AI key field at `draw.rs:~5994` and its save path `draw.rs:~6316`.
- C4 Commands: `enum Builtin` in `crates/app/src/items.rs` (title, extension, glyph, keywords, id), dispatch in `app.rs` (`match builtin`, ~4084), views in `enum View` (`app.rs:~301`) with footer hints, titles and placeholders nearby, ⌘K actions in `actions_for` (`app.rs:~3366`), footer primary label `primary_label` (`app.rs:~3535`). Hotkeys come for free through `CommandConfig`.
- C5 Obsidian URI (help.obsidian.md "Obsidian URI"): `open` (vault, file, path, paneType), `new` (vault, name, file, path, content, clipboard, silent, append, overwrite), `daily` ("accepts the same parameters as the new action"; needs the Daily notes plugin), `search` (vault, query). Values must be percent-encoded: "`/` must be encoded as `%2F` and space characters must be encoded as `%20`". Vault list: `~/Library/Application Support/obsidian/obsidian.json`.
- C6 Preview: the app has no Markdown renderer; `crates/core/src/markdown.rs` only converts. T6/T8 add a small block renderer; when `feat/notes` lands, consider switching it to `richtext::parse` (feat/notes `crates/core/src/richtext.rs:108`).
- C7 Files: Spotlight name search exists (`crates/macos/src/files.rs:15`), no folder walker, no file watcher: index on view open, no background watching.
- C8 Notes app (feat/notes, not merged when this plan was written): `crates/core/src/notes.rs` has `export_markdown` (`:247`) and the `Note` model with `pinned_at`/`deleted_at`; the floating window is `crates/macos/src/notes.rs` (`NotesPanel`); its ⌘K actions are still being wired (its T5/T6). Phase 3 must re-read the merged code; names may change.
- C9 Tests: loopback HTTP server `serve()` in `services.rs` (~4171) with real curl; app fixture `fixture()` in `tests.rs` with a temp `Store` and a readable `Bus`; core tests inline. Use these; no network in tests.
- C10 Manual checks for the user (Phase end): connect a real Notion token, search, capture to a page and to a database, open a result; pick a vault, search it, preview, open, new note, daily note with Obsidian closed and open; for Phase 3, send a note to both, edit it in Obsidian, change it in Ferrocast, and confirm the conflict toast.
- Risk items per task are in the task lines; T1 and T11 must be their own commits so they can be reviewed alone.
